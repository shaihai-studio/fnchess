## 分数关两处真实 bug 修复（2026-07-30 用户实测反馈）

### Bug A：分数关按钮变灰（应是黑底+青边框）
- 根因：`style.css:188-192` 只定义了 5 个 `#campaign-diff-*` 渐变色规则，**没有 `#campaign-diff-fraction`** → 回退 `.btn` 默认灰底。
- 修复：新增 `#campaign-diff-fraction { background: linear-gradient(135deg, #0d1f23, #050b0d); border: 2px solid #14b8a6; color: #14b8a6; }` + hover 规则。与 `campaign-level-badge` 的 teal `#14b8a6` 配色一致。

### Bug B：通关整数关后点分数关 → 1/2~1/20 全部锁住
- 根因：`renderCampaignLevelGrid`（UICampaign.js 原 ~590）`fracUnlocked` 只看 `getCampaignFractionUnlockedMax()`（=`fracCleared+1`）。分数关是独立进度，从未玩过则 `fracUnlocked = 1`，全锁。即便整数关通关 84/109 也无效。
- 修复：`fracUnlocked = Math.max(fracOwnUnlocked, cleared >= 1 ? 2 : 1)` — 整数关通关数 ≥1 时，至少解锁分数关 1/2 作为入口；分数关后续独立进度续接。
- 同步更新进度文本：`已通关 X/19，当前可进入 1/2（从整数关解锁）`，让 0 进度用户明白为何可玩。

### ⚠ 别再走弯路的项目约定
- 任何新增的 `#campaign-diff-*` / `#campaign-level-cell.*` 类别，必须**同时**配上 CSS 颜色规则，否则会回退到默认灰色看着像 bug。新增前先 grep `style.css` 确认同 ID 块已存在配色。
- 任何"独立进度"分支（如分数关/竞速关）若与主进度并存，要明确"主进度是否能解锁该分支"，并在 UI 文案里提示给用户。
