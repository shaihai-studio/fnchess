## 性能回归修复（已验证）
- 现象：相比 8f7d198c，网页加载极慢（10.3s）+ 主菜单掉帧。
- 根因（CDP CPU profiler 实测）：`index.html:9` 在 `<head>` 用**同步脚本**加载 `https://unpkg.com/peerjs@1.5.2/dist/peerjs.min.js`，占加载期 66% 主线程 JS 时间（~3.4s 编译/执行），阻塞整页解析与菜单渲染。但 peerjs 仅在用户点联机（P2PController.createRoom/joinRoom/createRoomWithCode 里 new Peer）时才需要，开局完全用不到。
- 修复：删除 head 里的同步 peerjs 脚本；在 P2PController 加静态 `ensurePeerJs()` 懒加载器（动态注入 async script，缓存 Promise），在三个联机方法开头 `await`；UIP2P.showP2PRoomModal 去掉 `typeof Peer` 拦截（连接失败在 P2PController 内提示）。
- 验证（headless chromium 实测）：加载 10303ms→3136ms，菜单 ~98fps，无长任务；懒加载 `before=undefined → after=function` 成功。
- 结论：卡顿与 UIController 模块化拆分无关，是 head 同步远程脚本所致。

## 修复「提交失败后保留解析式」开关无效（已验证逻辑）
- 现象：勾选 index.html 的 `keep-expr-toggle` 复选框后，提交函数解析式仍被自动清空。
- 根因：`files/js` 中**从未获取 `keep-expr-toggle` 元素、也从未读取其 `checked` 状态**；而每回合结束的 `roundComplete` 事件（UICore.js）和失败重试的 `prepareInputPhase` 事件监听器都**无条件调用 `clearExpression()`**，开关形同虚设（与模块化拆分无关，是当时加复选框时漏接逻辑）。
- 修复：`UICore.js` 的 `initUI` 缓存 `this.keepExprToggle`；`prepareInputPhase` 监听器改为「(事件 data.clearExpression===false) 或 (开关 checked) 时不清空」；`roundComplete` 监听器在清空前判断开关；`UIPhase.js` 的 `input_function` 分支进入时显式 `updateExpressionDisplay()` 保证保留的表达式重新渲染可见。无 lint 错误。
