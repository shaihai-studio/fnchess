## 0. 文档约定

- **推进方式**：按「模块」逐个分析，每完成一个模块把结论回填到第 5 节对应小节，并在第 4 节进度表打勾。**不追求一口气读完所有文件**，读一段、结论一段、改一段。
- **可信度标注**：
  - 【确凿】已逐行阅读源码确认
  - 【待确认】由代码线索推断，动手前需再核对
- **严重度**：🔴 致命（可被利用/崩溃/数据被篡改） / 🟠 严重（功能错乱/体验受损） / 🟡 一般（可读性/轻微隐患）
- **分析维度**（每个文件/模块都从这 5 个角度过一遍）：
  1. **屎山程度**：坏味道、过长函数、重复代码、神秘命名、复杂度、架构耦合
  2. **可优化点**：性能、结构、可维护性
  3. **漏洞/可利用**：安全、作弊、绕过
  4. **自相矛盾**：逻辑冲突、双写不同步、注释与实现不符
  5. **UI 问题**：卡死、层级错乱、状态不同步、按钮失效

## 0.5 审查方法论：三层闭环（为什么"地毯式读代码"不够）

### 核心认知：bug 分两类，只有一类能被"读代码"直接看到

| 类型 | 定义 | 静态读码能否发现 | 实例（本项目已修） |
|---|---|---|---|
| **结构性 bug** | 自相矛盾、双写不同步、屎山、死代码、显式漏洞、显式 UI 冲突 | ✅ 能，静态搜索擅长 | 签名明文、`RACE_TIERS` 双写、`.modal-content overflow` 覆盖 |
| **行为性 bug** | 运行时竞态、异步时序、状态机边界、事件监听器残留、交互体验、设备差异 | ❌ 难，要顺"运行时路径"推理 | splash keydown 残留、房主迁移后 peer 置 null 卡死、断线判罚不对称 |

> **结论**：单纯逐文件读代码，只能覆盖"结构性问题"，捞不动"行为性问题"。后者恰恰是本项目过去修掉的 bug 的大头。

### 三层闭环（每个模块都按这个顺序做）

1. **第一层 · 静态审查（主引擎）**：5 维度逐文件读 → 产出"结构性问题清单"。
2. **第二层 · 数据校验（脚本）**：对**数据驱动**的文件（`campaignLevels.js` 1.2 万行、`server/*.json`）写一次性校验脚本，用规则反查数据（关卡 ID 连续、参数符合规则手册、贴图/音频引用存在）。人眼读数据不可靠，脚本 100% 可靠。
3. **第三层 · 动态验证（跑起来）**：对**行为性 bug** 用下列手段定向收敛（见下）。

### 第三层：行为式 bug 怎么找（分层收敛，无法完全穷举）

1. **代码级时序分析（静态逼近行为，零成本）**：把关键布尔状态变量（`_rbMigrationActive` / `_reconnecting` / `_p2pMatchStarted` / `_p2pRoomDissolved` 等）的全部"置位/清除"点列出，做成状态转移表，找三类硬伤：
   - 置位后某路径没清 → **残留**（splash keydown 就是这类）
   - 清了没置位 / 漏复位 → **状态泄漏**
   - 两个异步回调都能改同一状态、谁先谁后没锁 → **竞态**
2. **运行时插桩**：在状态机转换点临时加日志，跑真实对局收集状态序列，抓"非法转换"。
3. **浏览器自动化（半自动）**：项目已有 `agent-browser` / `playwright-cli` / `Playwright MCP` 等 skill，可模拟点击/输入/断线。但 Canvas 游戏 + 真实 PeerJS 联机时序，纯自动化复现成本高，主要用于**本地/单人路径**（输入、表达式、关卡流程、UI 交互）。
4. **定向复现清单（人工/半自动）**：把已知高风险运行时路径列成 checklist，逐一触发——断线重连、房主迁移、多标签串号、刷新恢复、竞速中途退出。这类只能靠"顺着路径手动触发一次"确认，静态永远猜不准。

> **对"能不能找到所有 bug"的诚实回答**：不能。"所有 bug"没有客观全集。三层闭环能把**结构性问题全量覆盖 + 数据问题全量覆盖 + 行为性高价值问题收敛到 80%+**，但剩余的长尾（极端时序、小众设备、罕见交互组合）只能靠真实玩家暴露后回补。目标是"把高价值 bug 捞干净"，不是追求不存在的"零 bug"。

## 2. 全局速览结论（边做边更新）

### 2.1 架构层面的根本矛盾（已确凿）
1. **服务端"不参与对局却当权威裁判"**：对局全在 P2P/本地跑，进度、名次、难度、耐力全在客户端手里；服务端 `handleRaceScore` 只套公式，"你报什么我信什么"。这是刷分漏洞的总根源。
2. **双写不同步**：同一份业务常量在多处重复定义（如段位阈值 `RACE_TIERS` 在 `server/index.js` 与 `UIRaceBattle.js` 各一份，改一处忘另一处即错）。
3. **规则文档与实际代码脱节**：`函数棋完整游戏手册.txt` 中"游戏规则.txt 游戏内完全不加载"，改规则必须改代码。

### 2.2 屎山指数初评
- 不是"乱到读不懂"的烂山，是**"补丁叠补丁的复杂状态机 + 数据代码混杂 + 超大型单体文件"**。
- 重灾区排序：`campaignLevels.js`（数据硬编码）> `style.css`（无结构）> `UIRaceBattle.js`/`UICore.js`/`GameController.js`（巨型状态机）> `server/index.js`（多协议堆叠）。

## 4. 已完成模块的分析结论

### 4.1 M7 竞速联机（✅ 初步完成，2026-08-14）

**机制概览**（已讲解清楚，直白版）：
- 拓扑 = P2P 星型。房主固定 Peer id `race_<房间码>`，访客随机 `rg_xxx`；访客间消息由房主转发。
- 公平 = 房主生成 `seeds[]` + 统一 `goAt` 时间戳，全员对表 3-2-1 倒计时起跑，各跑各的关。
- 同步 = 访客→房主单向上报进度，房主 `_rbProgress` 权威合并快照广播。
- 防掉线 = 心跳 3s/9s → 访客重连 3s×20 → 房主迁移（选举 + 进度收集 + migration_done）。

**已发现漏洞（🔴）**：
1. **伪造签名直报刷分（最致命）**：① secret 明文在前端 `VerifyCrypto.js:123`；② `handleRaceScore` 无 `SIGN_GATE` 限速、无 IP 风控（对比 `handleSubmitScore` 有）；③ `place/totalPlayers/difficulty/stamina` 全客户端自报（`server/index.js:268-282`）；④ 去重键 `roomKey:playerId` 的 roomKey 也自报，换房间码可无限刷。
2. **双开洗分**：无登录，服务器无法区分同人两窗口；但竞速积分零和，效率低，伪签名才是捷径。
3. **伪造完成**：peer 消息零校验，第一名 `raceBattleDoEarlySettle` 本端直报 `place=1` 不等房主；非第一名伪造完成可触发 n-1 提前结算（DoS）。
4. **seeds 泄漏 + 本地跑关** = 自动答题外挂（纯前端宿命）。
5. **localStorage 恢复键篡改**：明文可改（但实时对局意义有限）。

**优化建议（三级）**：P0 = `handleRaceScore` 套限速+IP 风控、`host_register` 记房间参数+参与人集合供结算核对、去重升级房间级；P1 = 协议快照化、状态机单一枚举；P2 = 服务器中继权威计时（大改）。

### 4.2 M9/M10 签名与竞速结算（✅ 已发现致命漏洞，2026-08-14）

- `handleRaceScore`（`server/index.js:253`）与 `handleSubmitScore`（`server/index.js:830` 附近）**防护不对等**：后者有 `SIGN_GATE` 2s 限速 + `checkIpNewIdentity` IP 风控，前者全裸。
- secret 硬编码前端，HMAC 形同虚设。

**动态坐实（2026-08-14，协议黑盒测试 `server/protocol_test.cjs`，11/11 PASS）**：
- 已落地「第三层 · 动态验证」的第一块：用 Node 内置 `WebSocket` + `crypto` 伪造签名，模拟作弊玩家直报结算，零依赖、全自动。
- 测试坐实的漏洞（每组 PASS = 漏洞坐实，不是系统正常）：
  - **T1** 伪造 4 人房第 1 名 / 难度 7 / 耐力 4 → 服务端无脑给满额 `+68`（`raceDelta` 公式坐实）。
  - **T2** 同一 playerId 换 `roomCode` 连续 5 次均加分、全程无 `rate_limited` → 去重被绕过 + 竞速结算无 SIGN_GATE 限速。
  - **T6** 连续换房刷 40+ 局直冲「宇宙」(1600) 段，无任何上限/频率拦截。
  - **T3/T4/T5**（正向验证）同房去重生效、低段位保护、弃权下限 0，逻辑正确无 bug。
- 测试脚本即「作弊客户端」：用前端明文 secret 即可伪造合法 HMAC → 再次印证 secret 明文 = 防不住作弊。

### 4.3 M2 核心引擎 GameController.js（✅ 已完成，2026-08-14）

**规模与性质**：2401 行 God 类，糅合「回合状态机 + 双计时器 + 回合逻辑 + P2P 同步 + 闯关/竞速分支 + 历史记录」六种职责。补丁叠补丁（`function_result` 分支里有 40 行的"补齐推进 + 请求快照"防御逻辑，说明此前踩过多次死锁坑）。

**已发现 bug（静态审查，按严重度）**：
