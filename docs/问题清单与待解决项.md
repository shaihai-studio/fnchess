## 一、确凿 bug（已逐行核实源码）

### 1. （已排除）3P 模式 C 玩家 HUD —— 误报
> 经用户确认：**本项目不存在 3 人模式**（GameController 的 `players` 仅含 A/B，UI 与 HUD 也无任何 3P 痕迹）。原以为的"第三位玩家分数不显示"是建立在错误前提上的，不是 bug。已移除。

### 2. 🔴 P2P 创建/加入房间失败后按钮永久卡死
- 文件行号：`files/js/UIController.js:1030`、`:1057`（点击即禁用）、`:985-989`（onError 不复用）、`:924-925`（仅重开弹窗时恢复）
- 代码：
```js
// 点击创建/加入时
createBtn.onclick = () => { createBtn.disabled = true; ... this.p2pController?.createRoom(); };
// 失败回调
p2p.onError = (msg) => {
    this._updateP2PStatus('error', msg || '连接发生错误');
    this.showMessage(msg || '连接发生错误', 'error');  // 只弹消息，不复用按钮
};
// 恢复仅在重新打开弹窗时：
const cb = $('p2p-create-btn'); if (cb) cb.disabled = false;
```
- 现象：房间码错误 / 网络失败 / 超时等任何错误后，「创建房间」「加入房间」按钮保持灰色，提示停留；用户必须手动关闭弹窗再重开才能重试。
- 影响：联机失败路径无恢复入口，新手极易卡死。
- 建议：在 `onError` 与 `onDisconnected` 回调中把 `createBtn`/`joinBtn` 重新 `disabled = false`，并给出明确的重试提示。

### 3. 🟠 计时器显示负数 / 小数（无钳制、无取整）
- 文件行号：`files/js/UIController.js:5833-5834`
- 代码：
```js
updateTimer(remainingTime) {
    this.timerElement.textContent = remainingTime;
```
- 现象：`remainingTime` 可能为负数或小数（例如 P2P `onTimerSync` 传入对端剩余时间，可能是 `-0.12` 或 `12.34`），顶部计时直接显示成 `-0.12` 或 `12.34`。
- 影响：视觉不专业，且负数可能让人误以为逻辑出错。
- 建议：`this.timerElement.textContent = Math.max(0, Math.ceil(remainingTime));`

### 5. 🟠 响应式布局在旋转 / 设备切换时不刷新元素面板
- 文件行号：`files/js/ResponsiveLayout.js:80-130`
- 代码：
```js
updateLayout() {
    if (newDevice !== this.currentDevice) {
        this.applyLayout();          // 仅切换 body 的 device-* 类
        this.onDeviceChange(newDevice);
    }
    this.resizeCanvas();             // 只调 gameRenderer.resize()
}
```
- 现象：桌面 ↔ 移动端元素布局（底部 `elements-container` 网格 vs `inline-elements-card` 内联面板，由 `initDraggableElements()` 内的 `isMobileElementLayout()` 决定）只在「阶段变化」时切换。旋转手机 / 调整窗口后，`isMobileElementLayout()` 结果已变，但 `initDraggableElements()` 未重新调用，元素按钮布局错乱。
- 建议：在 `ResponsiveLayout` 的 `onDeviceChange` 或 `updateLayout` 中，通知 `UIController` 重新调用 `initDraggableElements()`（可派发自定义事件，UIController 监听后重建元素面板）。

### 8. 🟡 表达式显示区新增内容不自动滚到底部

### 9. 🟡 退出确认气泡无法点外部 / ESC 关闭，且再点退出不收起

### 10. 🟠 错误 / 警告提示仅 2 秒就消失

### P1（🔴）`addCellAt` 同类型格「删了不补」→ 画笔/矩形/直线/移动全链路丢格　【✅ 已修复】
- 文件行号：`files/js/ui/UIEditor.js:450-458`（`addCellAt`），调用点：单点落格 :530、画笔 `paintSegment` :493-503 + `handleDragMove` :709-715、矩形 `addCellRange` :459-469、直线 `addPathCells` :488-491、选区移动 `moveSelectionBy` :600-603 / `handleSelectMove` :655-658
- 代码：
```js

    const existingType = removeCellAt(level, cell);   // ① 无条件先删目标位
    if (existingType === type) return;                // ② 同类型：删了不补 → 格子消失！
    if (existingType && existingType !== type) {      // 异类型：删旧补新（覆盖）

```
- 现象：目标位置已有**同类型**格子时，先被 `removeCellAt` 删除，随即 `return` 不再 push → 该位置「原格被删、新格没落」，格子凭空消失。影响面：

  - **选区移动**到同类型格位置 → 该格被吞且选区格少一个。
- 影响：关卡编辑器最常见操作（涂格、框选移动）存在确定性数据丢失，且无撤销前无法察觉（历史整批记录，回滚也丢）。

- 开始行529：`list.every((m) => this._rbReadyMap[m.playerId])` —— 未跳过房主

房主的 `_rbReadyMap[hostId]` 从未初始化（始终 `undefined` → falsy），导致 `every()` 始终返回 `false`，按钮永远 disabled。

**定位**：`files/js/ui/UIRaceBattle.js` 行526-550（`raceBattleStart`），行440 的 `|| m.isHost` 条件在行529 缺失。

### Bug 11.2：大厅房间不显示/无法加入（PeerJS room code vs lobby room code 两套独立码）【✅ 已修复】

**症状**：房主在大厅创建房间后，房间在大厅列表不显示；或显示了但其他玩家点击加入后连接失败/无限等待。

**根因**：系统中有**两套独立的房间码**，互不对齐：

1. **PeerJS 房间码**：`raceBattleCreateRoom`（行305）自生成 6 位随机数（`Math.floor(100000 + Math.random() * 900000)`），用于 WebRTC DataChannel 连接
2. **Lobby 房间码**：`_createRaceLobbyRoom` → `lobby.hostRegister(opts)` → 服务端生成 lobby code，用于大厅列表展示

访客加入流程（`onJoinAccepted` 行1600-1605）用 lobby 返回的 code 调用 `raceBattleJoinRoom()` 去建立 PeerJS 连接，但 PeerJS 房间用的是另一个随机数 → 连接失败。

**定位**：
- `raceBattleCreateRoom`（UIRaceBattle.js 行298-324）：生成 PeerJS room code
- `_createRaceLobbyRoom`（UIRaceBattle.js 行1738-1752）：`hostRegister(opts)` 未传入 PeerJS code
- `onJoinAccepted`（UIRaceBattle.js 行1600-1605）：用 lobby code 当 PeerJS code 连接

### Bug 11.3：踢人不彻底（被踢者 Peer 连接未断 + 其他访客成员列表不更新）【✅ 已修复】

**症状**：房主踢一个人需要踢两次才生效；被踢者可能在列表中重新出现（幽灵成员）；其他访客的成员列表中不显示被踢者已被移除。

**根因**：踢人消息 `race_battle_kick` 只做了 UI 层通知，未同步到协议层：

1. `raceBattleKickMember`（行514-524）本地移除 `_rbMembers` 后发送 `race_battle_kick` 消息
2. 其他访客收到消息后（行1087-1090）只匹配 `targetId === this._rbMyId`——不匹配则**什么都不做**，成员列表不更新
3. 被踢者 `doLeave`（行595-608）调用 `_rbRoom.disconnect()` 断开连接，但 RaceRoomController 的 `members` 数组不变，后续重连/状态广播可能把被踢者重新加回来
4. 整个流程从未通过 `race_member_left` 协议通知 RaceRoomController 和管理此成员的连接

**定位**：`files/js/ui/UIRaceBattle.js`
- 行514-524（`raceBattleKickMember`）：发送 kick 但未通知 RaceRoomController
- 行1080-1091（`_raceBattleHandleMessage` race_battle_kick 分支）：非被踢者不做成员列表更新
- 行595-608（`raceBattleDoLeave`）：断开 Peer 但 RaceRoomController 未感知

### Bug 11.4：被踢无提示（消息送达不确定导致 toast 未显示）【✅ 已修复】

**症状**：房主踢人后，被踢者没看到任何提示（如"你已被房主移出房间"），感觉房间突然消失了。

**根因（两级）**：

1. **消息不可靠送达**：kick 消息通过 WebRTC DataChannel 发送（`_rbRoom.send` 行516）。如果被踢者刚好网络抖动或 Peer 连接不稳定 → 消息丢包 → toast 永远不会显示。
2. **toast 体验不佳**：toast 元素（index.html 行730 `#race-battle-toast`）在 body 级别、不在 modal 内，理论上 `raceBattleDoLeave` 的 `hideModal` 不会隐藏它。但 1.8s toast 刚弹出时 `doLeave` 同步关闭了弹窗面板，用户看到的是"主界面突然回来"而非"被踢了"。

**定位**：
- `raceBattleKickMember` 行516：`send()` 无重试/确认机制
- `raceBattleDoLeave` 行599：`hideModal` 与 toast 时间窗口重叠
- `_raceBattleHandleMessage` 行1087-1090：被踢处理无 ACK

### Bug 11.5：raceBattleCreateRoom 异步不等待（lobby 注册时 PeerJS 房间尚未就绪）【✅ 已修复】

**症状**：房主创建房间后，lobby 注册成功（房间出现在大厅列表），但访客加入时 PeerJS 连接失败（房间不存在或尚未就绪）。

**根因**：`_createRaceLobbyRoom`（行1736-1752）中 `raceBattleCreateRoom()` 创建 PeerJS 连接是异步的（包含 `_raceBattleInitRoom → _rbRoom.create()` 含 PeerJS peer 初始化与等待），但调用后**不等待就立即执行 `lobby.hostRegister(opts)`**。如果 PeerJS 创建失败或尚未完成，lobby 已经注册但 Peer 房间不可用。

**定位**：`_createRaceLobbyRoom`（UIRaceBattle.js 行1717-1753）行1736→1738 无 await/Promise 等待。

### Bug 11.6：房主在大厅房间列表中不显示自己【✅ 已修复】

**症状**：房主创建房间后，在大厅列表中点进去详情，只看到 1 个空位，看不到房主自己的名字和头像。

**根因**：`_createRaceLobbyRoom` 的 `hostRegister(opts)` 未传入 `playerInfo`（昵称、ID 等），服务端可能未将房主计入房间成员列表。

**定位**：`_createRaceLobbyRoom`（UIRaceBattle.js 行1739-1745）opts 仅含 mode/maxPlayers/longLived/stamina/difficulty，缺少 playerInfo/nickname/playerId。

### 修复记录（2026-08-11，六条全部落地）

- **11.1**：`raceBattleStart`（`UIRaceBattle.js`）就绪检查改为 `list.every((m) => m.isHost || this._rbReadyMap[m.playerId])`，跳过房主，与渲染逻辑（行440）对齐；房主就绪状态不再被 `undefined` falsy 卡死，开始按钮正常启用。

### U7. 【一般】竞速对局中断/迁移期间玩家被弹窗锁死，无任何操作出口（设计如此但体验风险高）
