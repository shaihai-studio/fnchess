| 项 | 决策 |

## 2. 数据库设计（SQLite，better-sqlite3）

库文件：`server/db/function_chess.db`，开启 `PRAGMA journal_mode = WAL;`。

### 2.1 建表 SQL

```sql
-- 用户主表
CREATE TABLE IF NOT EXISTS users (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    username      TEXT UNIQUE NOT NULL,          -- 登录名（唯一，不可改）
    nickname      TEXT NOT NULL,                 -- 展示昵称（可改）
    password_hash TEXT NOT NULL,                 -- scrypt 输出（含盐参数编码）
    salt          TEXT NOT NULL,                 -- 随机盐 hex
    bound_uuid    TEXT,                          -- 旧 localStorage UUID（并入用）
    phone_hash    TEXT UNIQUE,                   -- 预留：手机号 HMAC 哈希（脱敏反刷）
    phone_verified INTEGER DEFAULT 0,            -- 预留：0 未绑 1 已绑
    created_at    INTEGER NOT NULL,              -- 注册时间戳(ms)
    last_login_at INTEGER NOT NULL DEFAULT 0,    -- 最近登录
    updated_at    INTEGER NOT NULL DEFAULT 0
);

-- 登录令牌
CREATE TABLE IF NOT EXISTS tokens (
    token      TEXT PRIMARY KEY,                 -- 随机 64 hex
    user_id    INTEGER NOT NULL,
    created_at INTEGER NOT NULL,
    expires_at INTEGER NOT NULL,
    last_seen  INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX IF NOT EXISTS idx_tokens_user ON tokens(user_id);

-- 账号进度（字段级存储，服务器为权威源）
CREATE TABLE IF NOT EXISTS progress (
    user_id       INTEGER PRIMARY KEY,
    lr_value      INTEGER DEFAULT 0,
    lr_updated_at INTEGER DEFAULT 0,
    tt_value      INTEGER DEFAULT 0,
    tt_updated_at INTEGER DEFAULT 0,
    elo_value     INTEGER DEFAULT 1200,
    elo_updated_at INTEGER DEFAULT 0,
    updated_at    INTEGER DEFAULT 0
);

-- 预留：绑定验证码（未来手机号绑定用，当前不启用）
CREATE TABLE IF NOT EXISTS bind_codes (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id    INTEGER NOT NULL,
    target     TEXT NOT NULL,                    -- 预留 target（如手机号 hash）
    code_hash  TEXT NOT NULL,
    expires_at INTEGER NOT NULL,
    used       INTEGER DEFAULT 0
);
```

> 说明：
> - `username` 唯一（小写归一化存储，`UNIQUE` 约束天然防重名注册）。
> - `progress` 采用**每字段独立 updatedAt**，支撑字段级合并。
> - `phone_hash` / `bind_codes` 现不启用，仅留字段/表结构，未来接入不改表。

### 2.2 密码哈希

复用 Node 内置 `crypto`（server 目前未引入，需新增 `const crypto = require('crypto')`）：

```js
const crypto = require('crypto');
// 加盐哈希（scrypt）
function hashPassword(password, salt) {
    return crypto.scryptSync(String(password), salt, 64).toString('hex');
}
// 注册：salt = crypto.randomBytes(16).toString('hex')
// 存：password_hash = hashPassword(pwd, salt)
// 校验：timingSafeEqual 对比
function verifyPassword(password, salt, hash) {
    const h1 = Buffer.from(hash, 'hex');
    const h2 = Buffer.from(hashPassword(password, salt), 'hex');
    return h1.length === h2.length && crypto.timingSafeEqual(h1, h2);
}
```

- 密码长度：6~32 位，含字母/数字/符号至少一类。
- 登录失败锁定：同一 username 连续 5 次失败 → 锁定 10 分钟（内存 Map 即可，不必落库）。

## 3. 接口定义（HTTP REST，`/api/*`）

统一约定：
- 请求/响应均为 JSON。
- 需鉴权的接口带 `Authorization: Bearer <token>`。
- 业务码 `code` 便于前端区分提示。

### 3.1 注册 `POST /api/auth/register`

请求：
```json
{ "username": "alice", "nickname": "爱丽丝", "password": "abc123", "uuid": "旧localStorage的UUID(可空)" }
```
校验：
- username：2~20 字符，仅字母/数字/下划线/中文，小写归一化后查重。
- nickname：1~10 字符。
- password：6~32 位。
- 防刷：IP 滑动窗口限流（见 §5）。

成功响应：
```json
{ "ok": true, "token": "64hex", "userId": 1, "nickname": "爱丽丝", "serverTime": 1730000000000 }
```
逻辑：
- 建 user；若带 `uuid`，写入 `bound_uuid`，并把该 uuid 名下旧排行/进度并入（见 §4.3）。
- 返回 token（自动登录）。

### 3.2 登录 `POST /api/auth/login`

请求：
```json
{ "username": "alice", "password": "abc123", "uuid": "当前设备localStorage的UUID(可空)" }
```
成功响应：同上（token / userId / nickname / serverTime）。
逻辑：
- 查 user → 校验密码 → 生成 token（30 天有效期，可滑动续期）。
- 若带 `uuid` 且与 `bound_uuid` 不同 → 触发并入/绑定（§4.3）。
- 失败：`{ ok:false, code:'bad_credentials' | 'locked' }`。

### 3.3 登出 `POST /api/auth/logout`

请求：`{ "token": "..." }`（或 header）。
逻辑：删除该 token 记录。

### 3.4 当前用户 `GET /api/me`

鉴权。返回 `{ userId, username, nickname, boundUuid, createdAt }`。

### 3.5 改名 `POST /api/me/nickname`

请求：`{ "nickname": "新昵称" }`
逻辑：更新 nickname，同步到排行榜昵称（见 §4.4 迁移）。

### 3.6 改密 `POST /api/me/password`

请求：`{ "oldPassword": "...", "newPassword": "..." }`
逻辑：校验旧密码 → 更新哈希 → 使该用户所有 token 失效（除当前）。

### 3.7 进度拉取 `GET /api/sync/pull`

鉴权。响应：
```json
{
  "ok": true,
  "serverTime": 1730000000000,
  "progress": {
    "lr":  { "value": 2500, "updatedAt": 1730000000000 },
    "tt":  { "value": 120,  "updatedAt": 1730000000000 },
    "elo": { "value": 1250, "updatedAt": 1730000000000 }
  }
}
```

### 3.8 进度推送 `POST /api/sync/push`

请求（字段级，可只传有改动的字段）：
```json
{
  "progress": {
    "lr":  { "value": 2600, "updatedAt": 1730000100000, "dirty": true },
    "tt":  { "value": 120,  "updatedAt": 1730000000000, "dirty": false }
  },
  "serverTime": 1730000090000
}
```
逻辑：
- 对每个字段，`updatedAt > 服务器该字段 updatedAt` → 更新（服务器采信）。
- 否则忽略（服务器值更新）。
响应返回合并后权威 `progress`。

### 3.9 预留：绑定手机号相关接口（不启用，仅文档占位）

`POST /api/auth/send_bind_code` / `POST /api/auth/bind_phone` —— 未来做反刷绑定时启用。

## 4. 前端设计

### 4.1 新增模块

| 文件 | 职责 |
|---|---|
| `files/js/AuthService.js` | 注册/登录/登出/me/改名/改密；token 管理 |
| `files/js/ProgressSync.js` | 本地进度字段模型 + 拉/推/合并 + 异常检测 |

### 4.2 本地进度字段模型（localStorage，键 `function_chess_progress_v2`）

```js
{
  "lr":  { "value": 2500, "updatedAt": 1730000000000, "serverSyncedAt": 0, "dirty": true },
  "tt":  { "value": 120,  "updatedAt": 1730000000000, "serverSyncedAt": 0, "dirty": false },
  "elo": { "value": 1250, "updatedAt": 1730000000000, "serverSyncedAt": 0, "dirty": false }
}
```

### 4.3 异常检测 / 双保险策略（核心）

**服务器为时钟权威**：每次 pull/push 带 `serverTime`，客户端算 `offset = serverTime - clientTime`，比较时统一用服务器时间。

**三种异常信号（任一命中 → 服务器反向同步回本地）：**

| 信号 | 判定 | 动作 |
|---|---|---|
| 时钟回退/清零 | 某字段本地 `updatedAt` < 已知 `serverSyncedAt`，且 `dirty=false` | 服务器值覆盖本地 |
| UUID 丢失/换新 | localStorage 主键缺失或变化 | 用账号 `bound_uuid` 关联的旧数据找回 |
| 首次登录无档案 | 本地空，但账号在服务器有历史 `progress` | 服务器完整拉回 |

**保守合并原则（防误覆盖）：**
- **仅当 `dirty=false` 且服务器 `updatedAt` 严格更高** → 服务器覆盖本地。
- **若 `dirty=true`**（本地有未同步改动）→ **绝不反向覆盖**，向上推。
- 冲突仲裁为**字段级**（lr/tt/elo 各自按 updatedAt 取新），非整条覆盖。

**触发时机：**
- 登录成功后 / 每次启动：做一次完整 reconcile。
- 每次 pull 成功：顺带检测三种信号。
- 服务器不可达：不动本地、不标记丢失（避免断网误判）。

### 4.4 UUID → 账号并入迁移

- 注册/登录时提交 `uuid`。
- 服务器查 `bound_uuid` 关联的旧排行榜记录（lr/tt/elo/race/rtN），按 `userId` 并入 `progress` 与排行榜。
- 若该 uuid 名下分数高于账号现状 → 采用（按字段 updatedAt 取新）。
- 老 UUID 排行榜记录仍保留（不影响他人），但前端改为用 `userId` 展示。

### 4.5 排行榜主键切换

现有 `/lobby` WS 的 `submit_score` / `query_leaderboard` / `query_player_elo` 等，`playerId` 字段升级为**可携带 `userId`**：
- 已登录 → 用 `userId` 作为排行榜主键（同一账号多设备共享排名）。
- 未登录（休闲）→ 退回用 `playerId`（UUID），行为与现状一致。
- `isMe` 判断改为 `userId === 我的userId` 或 `playerId === 我的uuid`。

## 5. 反刷 / 恶意注册防御（分层）

沿用并升级现有 IP 风控思路，新增**滑动窗口**（修复原固定窗口「59:59 + 00:01 双打满」漏洞）：

```js
const IP_REGISTER_WINDOW = 3600 * 1000; // 1h 滑动窗口
const IP_MAX_REGISTER = 10;             // 每 IP 1h 最多注册 10 个
const ipRegCounts = new Map();          // ip -> [{ts}, ...]（时间戳数组）
function checkIpRegister(ip) {
    const now = Date.now();
    const arr = (ipRegCounts.get(ip) || []).filter(t => now - t < IP_REGISTER_WINDOW);
    if (arr.length >= IP_MAX_REGISTER) return false;
    arr.push(now);
    ipRegCounts.set(ip, arr);
    return true;
}
```

分层：
1. **基础校验**：username/password/nickname 规则；username 唯一（DB 约束）。
2. **IP 滑动窗口限流**：如上，1h / 10 次注册。
3. **登录失败锁定**：同一 username 5 次失败锁 10 分钟（内存 Map）。
4. **全局熔断**：注册接口 QPS 超阈值 → 临时 503（进程内计数）。
5. **图形验证码**：MVP 先用占位（不做真图），正式可接腾讯云/阿里云验证码（预留接口）。
6. **设备指纹（预留）**：登录/注册带设备指纹字段，未来启用。

> 说明：手机号反刷绑定暂缓，仅预留 `phone_hash` 字段与 `bind_codes` 表、`send_bind_code`/`bind_phone` 接口占位。

## 7. 风险与注意事项

- **登录必须走 HTTPS**：密码/token 明文传输不可接受；现有 80 端口 HTTP 需前端/后端同时改造，或仅 `/api/*` 走 HTTPS。
- **`better-sqlite3` 原生依赖**：服务器需有编译工具链或可用预编译二进制；若服务器受限，备选 `node:sqlite`（需 Node≥22.5）。
- **排行榜去重/防刷保留**：现有 `submit_score` 的 HMAC 签名、nonce、闸门、IP 新身份风控等逻辑**不删除**，仅叠加 `userId` 维度。
- **兼容老前端**：`playerId` 字段保留，未登录玩家行为不变，避免破坏已有对局/榜单。
- **时钟权威**：所有同步以服务器时间为准，客户端只做 offset 校正，禁止用客户端裸时间戳做反向覆盖依据。
